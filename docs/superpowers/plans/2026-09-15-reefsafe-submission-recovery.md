# ReefSafe Submission Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce one credible, reproducible DOSM Datathon submission that ranks reefs for field verification without unsupported economic, causal, capacity, or policy claims.

**Architecture:** `scripts/run_preprocessing.py` and `scripts/train_models.py` remain the authoritative analytical pipeline. The notebook, web dashboard, Excel dashboard, report, figures, and submission package consume only artifacts generated by that pipeline; they do not reimplement model selection or invent additional calculations. Unsupported features are removed instead of replaced with new assumptions.

**Tech Stack:** Python, Polars, scikit-learn, SciPy, Jupyter, vanilla HTML/CSS/JavaScript, Excel-compatible workbook generation, Python `unittest`.

**Spec:** `data/raw/unstructured/competition_guidelines/DOSM-Datathon-2026-Booklet.pdf`

## Global Constraints

- Do not present fabricated, simulated, or fictional values as data or evidence.
- Use ReefSafe only as a screening queue for field verification, never as a legal visitor cap, closure order, causal attribution engine, or island revenue calculator.
- Every quantitative claim must be generated from a repository dataset with a precise provenance record.
- Use past-only temporal validation and retain the mean baseline in every model comparison.
- One pipeline must generate every reported metric, uncertainty interval, ranking, and chart.
- Do not add a new dependency unless the existing standard library and installed packages cannot perform the required check.
- The final package must contain the report PDF, working dashboard plus source and README, and an MP4 video under ten minutes using the real team identity.
- Execute tasks in risk order: Task 1, Task 5, Task 2, Task 3, Task 4, Task 6, Task 7, then Task 8.
- If written NOAA eligibility confirmation is unavailable when Task 2 starts, exclude NOAA from scored model features and retain it only as clearly labelled supporting context.
